# Standalone static DEX/APK symbol comparison

`dexdiff.py` runs the DexMeguviz CLI over the supplied before/after input sets and compares class, field and method definition/reference counts by exact symbol. It preserves each source occurrence and reports definitions and references separately. The result is an observation over the supplied inputs: it does not pair occurrences across versions, prove Java/ART resolution, or infer an exhaustive absence from an incomplete scope.

Each side defaults to incomplete. `--before-complete` and `--after-complete` explicitly record the caller's scope assertion. Code inputs follow `--before` and `--after`; optional repeated `--before-resource` / `--after-resource` inputs are appended after code inputs and may be resource-only APKs. At least one code input per side is required. Paths, slot order and occurrence IDs are retained as reported by the core; moving a file can change its slot identity.

```powershell
python cli/diff/dexdiff.py --exe path/to/dexmeguviz.exe --before old/base.apk --after new/base.apk new/split.apk --before-complete --after-complete
```

The tool runs six independent metadata scans per side. It requires a complete execution for every scan and verifies stable input SHA-256, snapshot and source identities across scans. The CLI and input files must remain immutable while the command runs. Both sides are rehashed after all scans, but this is not a file lock and cannot detect a transient change restored between checks or after the final check. A result limit, work/budget failure, malformed result, changed input or timeout before output returns a nonzero exit without writing JSON. With stdout output, a broken pipe or other I/O failure can leave partial bytes; callers must check the exit code. `--max-results`, `--max-work`, `--budget-mib` and `--max-input-mib` bound the underlying calls; output serialization is limited to 32 MiB after construction, not a total RSS promise. Input files and the CLI are read-only; temporary query JSON is removed when the process exits.

`--output PATH` instead publishes a complete successful JSON result through a temporary file in the same directory and an atomic replacement. A failed scan or pre-publication write leaves an existing target unchanged; successful publication replaces it. Input paths, the CLI, this script, their hard links, and output symlinks/reparse points are rejected as destinations. Output parents must exist. Callers must prevent concurrent writers: path checks and replacement are separate operations, and this is not a crash-durable directory transaction. With `--output`, JSON is not written to stdout; omit it to keep the original stdout behavior.

Each symbol includes before/after definition and reference occurrences, per-occurrence local-definition metadata, and counts of observed definitions. `no_observed_definition`, `one_observed_definition`, and `multiple_observed_definitions` are counts within the supplied static world, not runtime resolution decisions. `count_changed` compares counts only; `attributes_changed` compares multisets of raw access flags and known method-body presence across definitions and references without pairing occurrences. Code offsets are reported but do not compare bytecode contents. All symbols are emitted so equal counts do not conceal changed provenance. Strings are JSON-escaped and preserve their Unicode code points and isolated UTF-16 surrogates as exposed by the CLI.

## Optional raw code-item fingerprints

`--code-digest` additionally reads each supplied logical DEX (including stored or deflated APK entries), verifies the DEX SHA-256 and exact archive entry index/name against the snapshot, and emits `code_sha256` for each code-bearing method definition and `code_changed` for method symbols. The digest domain is `DexMeguviz:raw-code-item:v1` followed by NUL and the complete raw `code_item`, with only the four-byte `debug_info_off` normalized to zero. It includes the register/argument header, instruction code units, padding, try table and encoded catch handlers; absent bodies have null. Duplicate code offsets within one occurrence are read once. `--code-max-handler-items` bounds the sum of handler headers and typed handler pairs per side (default 1,000,000, maximum 10,000,000); over-limit or malformed input fails without producing a diff. DEX source sizes are checked against `--max-input-mib`, and one expanded DEX is held at a time; this is not a total RSS limit.

This is a raw-byte fingerprint, not a semantic or runtime equivalence test. Pool-index renumbering or non-semantic encoding changes can change the digest; conversely identical instruction indexes can refer to different pool contents across DEX files. Debug data itself is not included. An unchanged digest does not prove equivalent behavior or resolve cross-version occurrence pairing. Default output is unchanged when the option is absent.

This is an initial independent CI consumer; multi-rule sharing, full source resolution, device/ART, production BIL replacement, and the full P2-07 acceptance remain separate work.




## Optional cross-source reference candidates

`--reference-candidates` adds bounded static evidence to each reference and a snapshot occurrence delta. It performs no additional native scans, class loading or name-based fuzzy matching. For each exact class descriptor or exact field/method owner, name and type/prototype, it checks whether a definition belongs to the reference's own `source_index` and local reference index; the existing `has_local_definition` and declaration offset must agree or the entire diff fails. Other exact-symbol definitions are counted by distinct already-enumerated definition occurrences, including the same DEX bytes supplied in different slots. The reference retains its original `source_index`, `reference_index`, `occurrence_id` and raw metadata; candidates are not substituted for a resolved target.

Each reference gains `static_candidates.local_definition` (`observed`/`not_observed`), `other_source_definition_count`, `other_source_state` (`none_observed`/`one_observed`/`multiple_observed`), `candidate_count_is_lower_bound` and `runtime_resolution=not_evaluated`. The count is exact only for the supplied checked snapshots. When the input scope is incomplete it is also a lower bound relative to possible additional sources; zero means only no other definition was observed in the supplied inputs. Even a caller-declared complete scope does not authenticate the installed application or ClassLoader. No hierarchy lookup, first-match ordering, access verification, virtual dispatch, runtime binding or global absence is inferred.

Each symbol's `reference_candidate_summary` contains before/after counts grouped by local-presence and other-source observed-count. `bucket_counts_changed` compares these aggregate counts only; it does not pair individual references across versions, and false does not prove unchanged provenance or equivalent runtime behavior. `scope_claim_changed` records an explicit change in caller scope declaration. `reference_candidate_model.source_occurrences` lists occurrence IDs present only before, only after or in both, preserving each side's source order. It compares exact occurrence identity, which includes slot identity and content; moving/renaming an input can change this identity. Empty resource inputs can change input lists without adding DEX occurrences; inspect the existing `inputs` as well.

Without the option, output format and behavior are unchanged. Existing scan limits, output size limit, atomic output rules and nonzero failure handling apply; budget exhaustion is a failure, not an empty candidate list. This limited static view does not complete the P2-07 full resolution, cross-platform or CI acceptance.
