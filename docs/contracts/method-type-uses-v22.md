# Method type predicates, QueryIR v22

`method_defs` may combine metadata predicates and `using_types` with `using_strings`, `invokes`, or `field_access`. The query explicitly declares `type_uses` under `required_capabilities`. A `using_types` object has exactly one `all` or `any` array. Each item has a required `descriptor` text matcher and an optional integer `opcode`, restricted to 0x1c, 0x1f, 0x20, 0x22, 0x23, 0x24, or 0x25. An empty array preserves the existing Boolean identity: `all:[]` is true and `any:[]` is false. This syntax still requires the explicit capability and receives a v22 identity even if no type event is requested; an empty matcher alone does not decode method bodies. Existing text matching and query node/depth limits apply.

The query is an unordered direct method query; sorting, top-N, reflection, numeric and relation-graph combinations are not supported by this profile. `query:v22:` and a separate canonical domain distinguish these identities. The same checked instruction event may satisfy more than one matcher, as with existing quantified use predicates. Matching events belong to one source occurrence and one method definition; no common control-flow path, dataflow, loaded class, loader, or actual execution is implied. A future combination of general `type_uses` relation graphs with other event graphs is a separate capability and is not implemented by this leaf.

Metadata can short-circuit body collection. When needed, the method's checked decoder gathers all required fact families in one pass, under the existing query work, cancellation and owned-memory limits. A method without a body produces the existing no-body false witness; negation preserves the existing three-valued semantics. Malformed instructions, budget exhaustion and cancellation use the existing execution error/coverage rules; they must not become successful absence. Explicit source slots filter occurrences, and completeness reflects only the declared static scope. Jobs do not stream while scanning this profile: delivery is provisional and final status remains authoritative.

The existing C method row retains its layout. `dmg_result_get_method_type_identity_v1`, `dmg_result_get_method_witness_v1`, `dmg_result_get_method_type_witness_v1` and `dmg_result_copy_method_type_descriptor_v1` expose occurrence-local method ordinals, mixed witnesses and type descriptors. The descriptor copy capacity must equal the reported UTF-16 unit length, and invalid calls leave output unchanged. The old witness getter rejects this profile; v21 graph-only v3 getters reject it too. The CLI emits tagged type witnesses and the descriptor. Android uses a separate bounded v22 wire and dedicated Java/Kotlin sync and Job entry points. Output is copied and bounded; no runtime identity resolution is performed. Old profile identities and entry points retain their prior domains and contracts.
