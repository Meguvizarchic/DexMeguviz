# R8 shrink and host JNI check

`verify_r8_host.py` reads an actual AAR, checks its `classes.jar` and packaged consumer rules against the supplied same-source JNI evidence, verifies the recorded JNI and AAR source inputs against the current source root, and compiles fixed Java and Kotlin consumers. It runs the installed R8 twice: once for classfile output using the JDK as the Java library, and once for DEX output using the supplied Android platform jar and min API 27. The Kotlin 2.4.21 standard library is supplied as a host/library input, not bundled as program code.

The classfile output is executed on a Windows JVM with the same-source JNI library: graph Job, v15 and typed v15 calls must complete, and checked production classes must load from the shrunk output directory. The DEX output is inspected by the independent Python DEX metadata reader; NativeEngine native methods and constructors plus the JNI-looked-up `GraphResult.decode` must retain their names and descriptors. Native declarations must have no DEX code body, while constructors and the decoder must retain one. JNI staticness is checked even if R8 widens that decoder's Java visibility. The test records the observed visibility and confirms no `kotlin/` definitions are packaged as program code.

Pass the current source root, new output directory, AAR and source manifest, host JNI directory and summary, Kotlin compiler-input manifest, JDK, R8 jar, Android platform jar and the fixed Unknown DEX fixture. Inputs, classfile/DEX outputs and command logs are hashed. This is a fixed shrinker configuration and Windows JVM test; classfile and DEX outputs are separate R8 compilations. It does not execute DEX on Android, prove ART or R8 behavior for every consumer configuration, verify all exported Java API use, or establish runtime class-loader binding.
