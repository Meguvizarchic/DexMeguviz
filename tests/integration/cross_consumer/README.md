# Cross-consumer method-v1 verification

`verify_cross_consumer.py` builds a C caller against the supplied host core libraries, compiles the Kotlin caller against the actual AAR `classes.jar`, runs the supplied same-source CLI and compares their method QueryID, status, coverage, decision, reason, counters, candidate identities and ASCII text fields in this fixture. It independently reparses the fixed raw DEX through `tools/evidence_verifier/verify.py` and checks each CLI result, including complete-scope uniqueness and absence and incomplete-scope limits. Two controls deliberately forge a flag and an incomplete-scope absence claim and require rejection.

Pass the current source root, fixed host CLI and its Debug core/miniz libraries, the recorded core summary and source manifest, the AAR and source manifest, the same-source host JNI output and summary, compiler-input manifest, JDK and CMake paths. The output directory must not already exist. The runner records commands, input hashes before and after, output log hashes, the C executable and Kotlin test class hashes. It checks the AAR `classes.jar` and verifies that query and result classes load from that jar. The supplied static libraries are associated with the CLI by build directory and source manifest; their historical build hashes are not separately attested. CMake uses the Visual Studio 18 2026 generator in this host-specific test; the Kotlin standard library is supplied to the host classpath.

These six fixed queries cover enumeration, unique/absent/ambiguous and existence under incomplete scope, with complete-scope CLI oracle comparisons. The C and JNI implementations share the same native core and the Python oracle shares the DEX specification and authored semantics; this is not independent ART/DexKit execution. It does not cover multi-source, APKs, all QueryIR predicates, use witnesses, failure paths, Android, or full P2-08 acceptance.
